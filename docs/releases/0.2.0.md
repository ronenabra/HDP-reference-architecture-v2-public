# Release limitations and known security findings — 0.2.0

On **17 November 2026**, the release owner accepted the known dependency
vulnerabilities below for this sandbox release without dependency updates.
The findings remain open, including Critical and High findings. This decision
does not mean the dependencies are fixed or that the sandbox is suitable for
production or real patient data.

## Functional validation status

Version 0.2.0 ships the existing audited images. Full regression validation
and follow-up fixes are planned for 0.2.1. The [external dataset review](../datasets.md) verified the 1k archive and
all three bundles against the offline import contract. It did not run a live
import, Doctor workflow, 10k qualification or full sandbox regression.

HAPI's raw report also contains 83 matches from build dependency declarations,
including 11 Critical and 46 High. These declarations are separate from the
installed-library inventory and can name different versions. They have not been
silently removed or counted as additional installed libraries.

The six application npm lockfile audits found no registry-reported vulnerabilities.
The Node image findings come from inherited image packages, including npm's own
dependencies and zlib. These are different inventories.

## What the findings mean

The gateway has 486 distinct advisory IDs, HAPI's combined raw report has 183,
and PostgreSQL has 108. Some require particular architectures, protocols or
configuration. For example, the reported OpenSSL CVE-2026-31789 and Perl
CVE-2026-8376 cases require 32-bit builds; these images are amd64. Other findings
still need individual assessment. A private network does not make them harmless.

The PostgreSQL image's Critical Go TLS finding concerns its bundled `gosu`
startup utility, rather than the C database server. The HAPI image uses Java
21.0.11; the scan does not provide complete Java runtime coverage.

The dependency reports, software inventories and checksums must accompany the
matching image distribution. This acceptance does not replace license compliance
or functional testing.

## Accepted source-companion scan limitation

On **17 November 2026**, the release owner accepted leaving the image
license/source companion's nested safety review incomplete for the images distributed with 0.2.0.
This is a disclosed release limitation, not a remaining requirement to rerun the
review before publication. The incomplete scan is **not a safety PASS**.

The recursive scanner stopped on deliberately malformed archive regression
fixtures in upstream BusyBox and GCC source trees. A complete nested scan of the
final companion has not been established. Separate checks verified its member
paths and checksums, source/binary correspondence and license/source coverage;
those checks do not substitute for complete safety inspection.

A credential-bearing GCC Go core-dump test fixture discovered during review was
excluded from the corresponding-source package. The runtime-library sources and
build inputs remain, with the source adjustment and changed recipe documented in
the companion. The original unsafe archive and earlier trial companions are not
release artifacts. The accepted limitation applies to this prepared companion:

- File: `pcm-image-license-source-companion.tar.gz`
- SHA-256: `4cade405103f743660c7f8f2b8c6fe47e5772b9d95ee476ab96be08b37c239dd`
